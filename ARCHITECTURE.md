# A-Lab.tech Infrastructure & Architecture Overview

Этот документ описывает техническое устройство проекта для быстрого онбординга новых AI-агентов. Прочитайте это trước тем, как вносить изменения.

## 1. Stack & Tech (Сборка)
*   **Архитектура:** Классическая связка Vanilla HTML + CSS + JavaScript.
*   **Фреймворки:** Нет (React, Vue, Webpack отсутствуют). Файлы грузятся напрямую бразуером.
*   **CSS:** Глобальная система стилей в `index.css`. Используются CSS-переменные для цветов. Для некоторых уникальных страниц стили вписаны прямо в `<head>` (например, в `digital.html` или `design.html`).

## 2. Локализация (i18n.js)
*   **Механика:** Клиентский парсинг словарей из файлов `/lang/ru.json` и `/lang/en.json`.
*   **Geo-IP:** Язык по умолчанию определяется по IP при первом заходе через `ip-api.com` (с фолбеком на `ipapi.co`). Страны СНГ автоматически получают русский, остальные — английский.
*   **Кэширование:** Выбор сохраняется в `localStorage` (ключи `alab_lang` и версия конфига `alab_lang_v`).
*   **Версионирование:** При обновлении `ru.json` или `en.json` к ним добавляется параметр `?v=X` (например `?v=26.4`), чтобы сбросить агрессивное кэширование браузеров.

## 3. База данных & Контент (Supabase)
*   **Бэкенд:** Supabase (`supabase-client.js`).
*   **Движок кейсов (`cases-engine.js`):** Скрипт запрашивает у базы портфолио для текущего языка и категории (design, marketing, rd). Если английских кейсов нет в базе, скрипт имеет fallback на русские.
*   **Исключение (Digital):** Кейсы из раздела `digital` зашиты прямо (hardcoded) в `cases-engine.js` из-за ограничений таблицы в базе данных.
*   **Изображения:** Статика лежит локально в папке `/assets/img/`.

## 4. Обработка Форм & Telegram
*   Заявки с форм не идут на сторонние CRM. Они перехватываются JS-скриптом.
*   Отправляются через POST-запрос на приватную серверлесс-функцию в **Яндекс Облаке (Yandex Cloud)**.
*   Функция в Яндекс Облаке уже напрямую стучится в Telegram API и присылает данные в Telegram-бота владельца проекта. Это сделано для безопасности ключей.

## 5. Деплой (Выгрузка на live-сервер)
*   **Сервер:** Linux VPS (IP: 85.192.60.14).
*   **Директория на сервере:** `/var/www/html/`
*   **Процесс выгрузки:** Выполняется командой rsync с локальной машины:
    ```bash
    rsync -avz --exclude='.git' --exclude='node_modules' ./ root@85.192.60.14:/var/www/html/
    ```
*   **Контроль версий:** Все изменения локально коммитятся в `main` ветку на GitHub.

## 🔴 Strict Rules for Agents
1. Не ломать существующие механизмы fallbacks (резервных путей) в скриптах.
2. Не пытаться перевести проект на сборщики (Vite, Webpack), если об этом явно не попросили.
3. Осторожнее редактировать CSS: элементы глобальные.
4. При добавлении картинок всегда копировать их в `assets/img/` и сразу делать git commit.
